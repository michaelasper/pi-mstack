# Second design review

The goal is a maintainable full Cursor pstack port to pi using pi-loop and pi-subagents. Users keep upstream workflows, persistent Poteto Mode, and configurable model roles. Maintainers keep a pinned snapshot, reviewed updates, and one generated runtime tree. This review checks the repairs in `docs/design.md` against both first round reviews and `docs/research/pi-capabilities.md`.

**Verdict.** ACCEPT.

**Principles.** Model the Domain changed the role check into a state check. The design separates registry validity, known native conflicts, and unverified native eligibility. Boundary Discipline kept child execution with pi-subagents and scheduling with pi-loop. Prove It Works kept this verdict at design level. The specified real host tests remain implementation gates. Laziness Protocol ruled out a second native policy engine inside this package.

**Repair check.**

1. The fallback repair is closed. `docs/design.md` line 90 seeds the mapping registry from the upstream generator and adds the Pi terms named in round one. Line 92 derives all 17 role labels, classifies missing config and fallback rules as adapt-required, and requires hash-bound exact patches. Generation fails when a flagged fallback survives in active prose.
2. The discovery and preservation repairs are closed. Line 54 splits preservation by reason and exposure. Line 70 declares the exact extension, skill, and agent roots, keeps discovery away from `upstream/`, defines the shipped files, and requires the exact 58 top-level names in the packed artifact. Line 119 gives each generated link class a destination rule and requires link checks in the unpacked artifact.
3. The role repair is closed without duplicating native enforcement. Line 131 puts role data in a section independent of mode. Line 139 uses the session scoped model set for setup when it is nonempty and preserves out-of-scope choices with diagnostics. Line 143 reports known public setting conflicts, says "native preflight required" when eligibility cannot be established, leaves rejection with pi-subagents, and requires native rejection tests for scope, strict inheritance, per-agent limits, and thinking ceilings.
4. The mode and collision repairs are closed. Line 133 makes only the bare toggle, the off form, and native `/skill:poteto-mode <task>` guaranteed. It makes short command task forwarding wait for the real host prototype across TUI, RPC, print, JSON, and busy follow-up delivery. Line 151 requires ownership checks before activation, disable, input consumption, or forwarding, and it requires session start collision notices for suffixed commands and shadowed skill names.
5. The update repair is closed. Line 113 binds the review digest to every adaptation input under `tools/` and `port/`, including template-only changes. Line 115 specifies the atomic writer lock, owner evidence, token-checked release, and explicit repair for a dead local owner. Line 165 requires tests for stale digests, abandoned lock repair, interrupted acceptance, concurrent writes, mode-only drift, and deterministic regeneration.
6. The mandatory gate repair is closed. Line 88 states that a substitute must satisfy the original requirement and that dependent actions stay blocked when it cannot. It rejects blanket skip-and-continue behavior. Line 172 turns Shipping, required UI verification, and an unavailable explicit reviewer into blocked acceptance examples.
7. Test ownership is specified at design level. Line 72 assigns source acceptance and generation to the importer, mode and role configuration to the extension, controller state to pi-loop, and child state to pi-subagents. Lines 165 to 173 assign local fixtures, pure runtime tests, packed SDK tests, real CLI and RPC tests, dependency contract tests, tarball checks, adapter acceptance examples, and final independent reviews. This design approval does not require those tests to exist yet.

**Remaining blockers.** None.

**Residual limit.** This ACCEPT covers the design contract. It is not a runtime certification. Gates 4 to 6 must still prove packed loading, command lifetime, native child delivery, and provider-visible loop or monitor follow-up on the real host. Line 173 keeps live-model prose quality separate from scripted-provider contract tests. The consumer gains no Cursor service parity claim, and the maintainer gains no claim that native eligibility is guaranteed after settings change.
