# Environment support design for 0.3.0

## Goal

Remove the accidental mode alias. Add branch goals, context-derived session names, local glossary definitions, memory and RAG context sources, and usable native child tools and MCP integration.

## Proposed selection

Use the native-first candidate as the base. Muse's independent cross-judge accepted this selection. Codex requested the command-ownership and native-data disclosure corrections below. Fresh review of this revision remains required. Its contracts cover all six features without introducing a second provider registry, permission manager, or credential store. The callback-registry candidate adds shell execution and unresolved persistence policy without a required use case. Retain its useful requirements for attribution, deterministic provider ordering, explicit budgets, and cancellation.

| Criterion | Native-first | Callback registry |
| --- | --- | --- |
| Observable feature coverage | Complete command and retrieval contracts | Environment detail is stronger than goal and naming detail |
| Native lifecycle correctness | Separates branch goals, session names and child context | Leaves context persistence and overlays undecided |
| Trust and authority | Native tool dispatch and configured sources | Command execution and network declarations need extra enforcement |
| Configuration burden | Separate environment file, existing agent settings | Adds registry API and environment fields to role configuration |
| Executable verification | Specific packed child and MCP nonce checks | Useful tests, less precise child context delivery |

## User contract

- `/goal` reports the active branch goal. `/goal <text>` sets it without a model call. `/goal --clear` clears it. `/goal -- <text>` escapes reserved arguments. Mutations refuse busy sessions. Repeated values do not append duplicate events.
- `/goal` ownership is separate from mode ownership. Check command provenance, suffixed extension collisions and foreign prompt names. A foreign skill named `goal` uses `/skill:goal` and is not a collision. Ambiguous ownership refuses this package's goal mutation and naming even through its suffixed command. If duplicate extensions make bare `/goal` undispatchable, handle that exact bare token in input only to report the collision without inference. Do not intercept foreign suffixed commands or the removed typo namespace. Test all routes with zero package goal writes and zero unintended provider calls.
- Goal events have `{ version: 1, text: string | null }` under `pi-mstack/goal`. Read active ancestry. Bound text to 4 KiB UTF-8 and reject control characters except newline and tab. Explicit set or clear replaces unsupported state. Goals remain active with mode off and through compaction.
- Goal replies disclose native metadata-only persistence. A fresh session with no conversation is memory-only. No private persistence method, sidecar history, or fabricated user message is permitted.
- Name a never-named session once from the first accepted task as delivered to mstack's input hook or from a goal. Earlier native input transformers can change the text before this hook. Pi provides no original-text field, so earlier transformations can affect the name. The earlier raw-human-input guarantee was disproved by the review fixture and is replaced by this observable contract. Prefer a single Jira-style identifier parsed locally. Cap names at 80 Unicode code points. No naming model call or remote Jira lookup. Preserve any native name or explicit clear, including names on other branches. Ignore mode-only commands, unknown slash commands, custom wakes, extension input and child tasks. Capture raw input without naming in the input hook. Commit its pending candidate only at the matching accepted user run boundary, after checking session identity and native name history. Clear candidates on input consumed or replaced after capture, rejected, busy or extension-origin input. An accepted goal mutation can name immediately. Test authentication rejection and later input handlers that consume the request.
- Store a versioned naming-attempt event before setting the native name. Any prior attempt or session_info seals automatic naming. An interrupted attempt stays sealed. Naming off or invalid environment configuration prevents attempts.
- Stop owning the typo command, its completion and its collision namespace. Preserve historical notes and negative tests. Canonical mode behavior and image transport remain unchanged.

## Configuration and ownership

Keep `pstack/models.json` unchanged. Add `PI_CODING_AGENT_DIR/pstack/environment.json` with version `pi-mstack/environment/1`. A trusted project can supply `.pi/pstack/environment.json`. Use Pi's exported configuration-directory constant rather than hardcoding its project name.

The user file accepts `naming: "task" | "off"`, glossary entries and context sources. Missing configuration enables task naming and no context sources. Project configuration accepts glossary and sources, not naming policy. Invalid configuration is diagnosed and disables environment features rather than silently falling back. Read configuration afresh at each run and goal command. Invalid trusted project configuration invalidates the entire environment snapshot. Merge glossary by exact case-sensitive term, preserving user order and replacing values in place, then append new project terms. Preserve source order as user entries followed by project entries. Resolve project memory paths against ctx.cwd.

Glossary entries have `term`, `meaning`, and `availability: "available" | "conditional" | "unavailable"`. Project terms replace matching user terms. Render descriptions in one owned prompt section. Do not replace words in skills or equate services. An operator can define the local meaning of a term while describing the limits of the chosen service.

Sources are a discriminated union keyed by unique `id` across both scopes. Duplicate IDs fail rather than silently redirect an authorized source.

- Memory source has `kind: "memory"`, `path`, and `delivery: "automatic" | "on-demand"`.
- MCP source has `kind: "mcp"`, exact native `tool`, and `queryArgument`.

User memory paths are absolute explicit authorizations. Project memory paths stay within the trusted project after canonicalization, including symlink checks. Read bounded regular files only. Config files are capped at 64 KiB. Combined glossary is capped at 32 entries and 8 KiB. Sources are capped at four.

Pi owns MCP servers, authentication, exposure and child selection. The environment file contains no credentials, server launch commands or capability grants. No shell or HTTP adapter is added in this release. RAG can use an existing MCP search tool.

## Runtime modules

- `index.ts` retains mode and role composition, registers `/goal`, and supplies accepted raw input to naming. Parent-only behavior is inert in background native children. Foreground children explicitly load only the context extension.
- `goal.ts` owns command parsing, branch reduction, command replies and owned goal context.
- `naming.ts` owns deterministic title derivation and session-wide eligibility.
- `environment-config.ts` owns the schema, scoped reads, normalization and diagnostics.
- `context.ts` is a separately registered extension for both parent and explicitly configured bundled children. It owns glossary, automatic memory and the `pstack_context` retrieval tool.

Prefer small functions and schema-derived types. Do not add brands, wrappers or a general registry unless they enforce a concrete invariant. Session caches are per extension instance, never global.

`pstack_context({ source, query })` resolves only configured sources. MCP execution happens inside tool context through `ctx.executeTool()` and native permission hooks. The target tool must be callable in that child and match a native MCP identity beginning `mcp__` with server and tool components. It cannot target `pstack_context` or a generic native tool. Native failures remain failures, never evidence. A source entry never widens the native allowlist. Decode text results, attribute the source and return bounded failures. Memory retrieval shares the same size and attribution contract.

Automatic memory uses the `context` hook as transient attributed data. It is not a system instruction and is not appended to native history. Read once per run, retain a session-local snapshot for tool follow-ups, reset for the next run and tree/session replacement. On-demand retrieval is a real tool result and can persist in the transcript. Document that both forms reach the model provider.

Use a two-second deadline that bounds the caller's wait even when a provider ignores cancellation, 16 KiB per rendered result, 64 KiB aggregate rendered automatic context including attribution, 2 KiB query limit and bounded wrapper diagnostics without raw upstream errors. These limits apply to pi-mstack's own output, not an end-to-end redaction boundary. Native tool events can expose upstream results and errors. Native nested-call metadata can retain queries and raw errors. The MCP provider also has its own retention policy. Test oversized results and a secret-like error sentinel separately in wrapper output and native records. Combine cancellation signals, abort on shutdown and suppress stale delivery after session changes. Optional retrieval failure does not block ordinary tasks. It does not satisfy a task's explicit evidence requirement.

## Native child integration

Bundled agents explicitly load the packaged context extension using native `subagentOnlyExtensions`. Prove relative path resolution and duplicate suppression rather than assuming them. Keep default tool allowlists unchanged. Automatic configured memory and glossary reach children without granting extra tools.

Operators enable on-demand retrieval through native tool selection. Document a complete replacement `tools` override with `pstack_context` and `mcp:docs/search`, plus native `mcp.json`. Custom tools require their provider in native `extensions` or `subagentOnlyExtensions`. Do not use unsupported `options.tools` or a preflight management action.

Fresh children receive goals in their parent-authored task briefs, not by reading another session. Built-in MCP can support foreground children. Ambient adapter MCP requires background execution. Native policy remains authoritative in both cases.

## Verification and delivery

Build behavioral tests before each implementation unit. Use existing packed SDK, RPC, print and PTY fixtures. Add real native child extension-tool and local stdio MCP invocation with matching nonces in server logs, child results and provider-visible context. Add missing-provider, missing-tool, hidden-tool and trust rejection cases. A discovery listing is not execution evidence.

Keep Pi 1.5.0 as the pinned minimum unless an actual API incompatibility requires a version decision. Run critical integration against installed 1.5.2 as additional compatibility evidence. Do not claim version coverage from documentation reads.

The parent alone integrates. Session logic can be one isolated writer lane. Environment/context and its tests can be another lane. A generation/docs lane starts after interfaces are fixed. Changes to `port/` require reviewed importer acceptance and regeneration. Independent Codex and Muse reviews must accept final code after repairs. Package tests and remote CI precede release.

Prepare 0.3.0 if still available. Push a feature branch and open a PR because main is protected. The user requested release, but the supplied Always-pause gate still applies before irreversible publication. Inspect the failed prior trusted-publishing route before choosing a publish mechanism. Never move an existing release tag or reuse a published version.

## Principles applied

Model the Domain separates branch goal state from session-wide naming and uses a source union. Laziness Protocol removes the generic callback registry and second capability manager. Separate Before Serializing Shared State keeps implementation writers isolated and caches session-local. Prove It Works requires actual child MCP execution and archive verification.
